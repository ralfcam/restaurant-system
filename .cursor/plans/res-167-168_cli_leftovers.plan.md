- [x] The `now()` cutoff in the baseline weakens the check on every reset · `supabase/migrations/00000000000000_baseline.sql:941-947` · The baseline evaluates `now()` each time `supabase db reset --local` runs. A fresh database gets the reset time as its cutoff. Any seed or fixture row whose `created_at` falls before that time can have a null `reservation_id`. The legacy test in `tests/integration/pos/orders-persistence.integ.test.ts` depends on this: it inserts `created_at: "2020-01-01"` with a null reservation, and the database accepts it. The `created_at` column comes from the client and is writable by service-role callers. Any service-role insert that sends a past `created_at` therefore skips the requirement. Two fixes are possible: a fixed literal cutoff gives the same behavior on remote and local databases, and a trigger that compares against the immutable insert time removes the bypass. At minimum, record that `created_at` must not be client-supplied.
